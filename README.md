# StickTouch

**Your body is the controller.**  
웹캠이나 스마트폰 카메라 앞에서 몸을 움직이며 즐기는 **카메라 기반 모션 미니게임 플랫폼**.

> **현재 상태: 1차 실행형 웹 MVP 구현** — 카메라, 자세 추적, 스틱맨, 충돌 및 풍선 게임 1종의 코드가 추가되었습니다. 실제 기기에서의 최종 검증은 남아 있습니다.

## 어떤 게임인가요?

StickTouch는 Mac·노트북·스마트폰·태블릿의 카메라에 보이는 실제 플레이어의 움직임을 인식합니다. 화면 속 게임 오브젝트가 손·발·머리 등 신체 부위에 닿으면 터지거나, 받아지거나, 점수를 얻게 됩니다.

카메라 영상은 **배경을 제거하지 않고 그대로 사용할 수 있습니다**. 스틱맨(관절 연결선)과 가상 아이템은 화면 위에 그려집니다. 별도의 깊이 카메라, VR 장비 또는 게임 컨트롤러 없이 시작하는 것이 목표입니다.

### 예상 플레이 예시

| 게임 | 화면 구성 | 조작 |
| --- | --- | --- |
| **사방 터뜨리기** | 플레이어가 화면 가운데, 상하좌우에서 풍선/아이템 등장 | 손·발·머리 터치 영역으로 물체 터뜨리기 |
| **과일 바구니** | 실제 카메라 영상이 화면 아래쪽에 작게 표시되고, 위에서 과일 낙하 | 양손 사이 또는 몸에 연결된 가상 바구니로 받기 |
| **포즈/리듬** | 따라 할 동작/목표 위치가 표시됨 | 손·발·몸 위치를 맞춰 득점 |

## 화면 표시 모드

실시간 자세 인식과 게임 판정은 그대로 유지하면서 **표현만 3가지 방식으로 바꿉니다**.

| 모드 | 플레이어 표시 | 배경 |
| --- | --- | --- |
| **Camera** | 실제 카메라 영상, 스틱맨 숨김 | 실제 촬영 배경 |
| **Camera + Stickman** | 실제 영상 위에 관절/연결선을 겹쳐 표시 | 실제 촬영 배경 |
| **Stickman** | 실제 영상 숨김, 스틱맨만 표시 | **가상 게임 배경** |

모드는 게임 중에도 전환할 수 있도록 설계합니다. 관절의 **터치 영역 원 표시 ON/OFF**는 화면 모드와 독립적으로 설정합니다.

## 원형 터치 영역

인식된 관절/부위는 **원형 히트박스**로 취급합니다. 손·발·머리 및 게임별로 필요한 신체 부위를 선택할 수 있습니다.

- 크기 배율 선택: **정밀 70% / 기본 100% / 넉넉 150%** (초기 제안, 최종 값은 테스트로 결정)
- 세부 조절: **50~200%** 범위 검토
- **실제 터치 판정 크기**와 **원 표시 여부**는 별도 옵션
- 확대하면 목표물 터뜨리기는 쉬워지지만, 장애물 회피는 어려워질 수도 있음
- 신체 크기·영상 배율·좌우 반전·카메라 배치를 고려한 좌표 보정

## 기술 방향 (계획)

- **플랫폼**: Mac/데스크톱 및 모바일 브라우저 우선
- **입력**: 사용자 카메라 (권한 요청 후 기기 내 처리)
- **동작 추적**: MediaPipe Pose Landmarker (웹) 검토
- **게임 그래픽**: 초기는 2D Canvas 오버레이; 3D가 꼭 필요한 게임은 추후 평가
- **구현 언어**: TypeScript 권장
- **주요 모듈**: 카메라, 관절 추적, 화면 좌표 변환, 원형 히트박스, 게임 엔진, 표시 모드, 게임별 모듈
- **개인정보 원칙**: 영상/추적 데이터는 기본 로컬 처리, 서버 업로드·저장·녹화 없음
- **초기 범위 제외**: 사람 배경 분리, 정밀 손가락 집기, 실제 깊이 측정, 정교한 3D 컵 쌓기

위 항목은 채택을 검토할 **기술 계획**이며 설치 완료된 라이브러리나 구현된 기능 목록이 아닙니다.

## 개발 브랜치 정책

**모든 개발은 `dev`에서 진행합니다.** `main`으로의 반영은 요청받았을 때에만, 검증 후 **진짜 fast-forward 방식으로만** 진행합니다.

```bash
# 개발
git clone https://github.com/White-Fantail/sticktouch.git
cd sticktouch
git switch dev

# main 반영 (별도 승인/테스트 후, main이 dev의 조상일 때만)
git fetch origin
git merge-base --is-ancestor origin/main origin/dev
# main의 작업 트리가 깨끗한 것을 확인한 뒤
git switch main
git pull --ff-only origin main
git merge --ff-only origin/dev
git push origin main
```

`main`의 merge commit / squash / GitHub rebase-merge를 fast-forward 대체 수단으로 사용하지 않습니다. 상세 안전 규칙은 [AGENTS.md](AGENTS.md)를 따릅니다.

## 개발 환경

React + TypeScript + Vite 웹 앱으로 초기화되었습니다. 아래 **실제 웹 앱 실행하기**를 참고하세요.

## 안전과 접근성

카메라 접근은 사용자 동의 후에만 수행하고, 추적 상태를 명확히 표시합니다. 게임 플레이 전 주변 장애물을 치우고 안전하게 움직일 공간을 확보해야 합니다. 관절을 놓치거나 인식이 중단된 경우에는 잘못된 판정을 줄이고 안내를 제공하도록 설계합니다.


## 실제 웹 앱 실행하기

StickTouch는 **단일 React + TypeScript + Vite 웹 앱**입니다. PC/Mac과 모바일이 동일한 관절 인식·좌표 변환·게임 로직을 공유합니다.

```bash
git clone https://github.com/White-Fantail/sticktouch.git
cd sticktouch
git switch dev
npm install
npm run dev
```

데스크톱 브라우저에서 터미널에 표시되는 `http://localhost:5173`을 엽니다. 카메라 사용을 허용하고, 세 가지 화면 모드를 바꿔 보거나 원형 터치 범위를 조절하고, **풍선 터뜨리기**를 60초 동안 플레이해 보세요.

**모바일 실기기:** 로컬 개발 서버의 일반 `http://192.168.x.x:5173` 주소는 카메라 권한을 쓸 수 없는 경우가 많습니다. **GitHub Codespaces의 HTTPS 포트**나 신뢰할 수 있는 HTTPS 개발 터널에서 테스트하세요. `dev` 브랜치의 **Vercel 자동 Preview 배포는 빌드 한도 보호를 위해 비활성화**했습니다. `main`에 fast-forward 반영되면 Vercel이 자동 배포합니다. 빌드 명령은 `npm run build`, 결과 폴더는 `dist`입니다.

```bash
npm run test     # 좌표, 미러링, hitbox, 충돌 판정 테스트
npm run check    # TypeScript 검사
npm run build    # 타입 확인 + Vite 프로덕션 빌드
npm run preview  # 로컬 빌드 결과 확인
```

MediaPipe의 WASM은 `cdn.jsdelivr.net`에서, Lite pose 모델은 `storage.googleapis.com`에서 최초 다운로드됩니다. 게임 중 카메라 프레임은 브라우저 내에서 처리하며 서버로 전송하거나 저장하지 않습니다. 초기 로딩에 인터넷이 필요하고, 호스트/기기별 카메라 접근·모델 성능을 실기기에서 검증해야 합니다. 영상은 녹화하지 않습니다.

현재 1차 MVP: 내장/모바일 카메라, 전후면 카메라 선택, 3가지 화면 모드, 터치원 보기/숨김, 크기 50–200%, 실시간 포즈 추적, 스틱맨, 60초 풍선 게임. 자세한 결정/남은 작업은 [AGENTS.md](AGENTS.md)와 [제품 명세](docs/PRODUCT_SPEC.md)를 참고하세요.


## GitHub Codespaces로 설치 없이 테스트

1. GitHub 저장소에서 **dev 브랜치**를 선택하고 **Code → Codespaces → Create codespace on dev**로 실행합니다.
2. 터미널에서 `npm run dev`를 실행합니다. 의존성은 Codespace 생성 시 자동 설치됩니다.
3. 하단 **PORTS**에서 5173번 포트를 찾아 **HTTPS**로 전환한 뒤 브라우저에서 주소를 엽니다.
4. 카메라 권한을 허용하면 PC나 모바일에서 테스트할 수 있습니다. 모바일로 옮겨 테스트하려면 같은 GitHub 계정으로 비공개 포트에 접근하거나 사용자 책임하에 포트 공개 여부를 선택하세요.

Codespaces는 일시적인 개발 서버이지 상시 운영되는 배포 URL이 아닙니다. 웹 카메라 권한을 위해 모바일에서도 HTTPS로 열린 주소를 사용해야 합니다. 장기간 실행하면 Codespaces 사용량에 따라 비용이 발생할 수 있습니다.

## 손바닥 정밀 추적 실험 (2026-10-21)

- 기존 Pose Landmarker (전신) 외에 **MediaPipe Hand Landmarker** (최대 양손, 각 21개 지점)를 추가했습니다.
- 손목(Hand 0)과 손가락 기저관절(5/9/13/17)의 가중 중심을 **손바닥 터치 앵커**로 사용합니다. Pose 손목과의 가까운 거리로 손을 연결하므로 좌우 반전 표시와 무관하게 플레이어의 왼손/오른손을 구분합니다.
- Hand가 손을 못 찾거나 실행을 지원하지 않으면 Pose의 손목+손가락 또는 팔꿈치 연장점을 사용합니다. 값은 부드럽게 보간되어 화면 모드 변경 시에도 동일한 게임 판정 좌표를 사용합니다.
- 게임 설정의 **손바닥 정밀 추적 ON/OFF**로 실제 위치/반응속도를 비교할 수 있습니다. Hand 감지는 Pose보다 낮은 빈도로 실행하고 기기에서 처리 시간이 길면 자동으로 횟수를 줄입니다.
- Hand 모델을 추가 다운로드해야 하므로 첫 진입이 느려질 수 있습니다. Chrome PC/Android 및 iOS Safari의 실기기 성능·정확도·발열 검증이 필요합니다. 서버에 영상/손 추적 데이터를 저장하지 않습니다.
- 테스트 추천: 손가락을 펼쳐 손목 원이 손바닥으로 이동했는지 보기 → 양손 교차 → 한 손을 잠시 가리기 → 100%/150% 판정 비교 → 손바닥 정밀 추적 ON/OFF 비교. 모바일에서 프레임 저하가 크다면 OFF로 플레이 가능합니다.


## 손바닥 추적 ON/OFF 동작과 진단 표시 (2026-10-21)

**Hand 모델 사용 ON**은 `Hand Landmarker`를 실행해 손당 21개 랜드마크 기반 손바닥 중심을 우선 적용하며, 인식에 실패하면 Pose로 추정합니다. **OFF**는 Hand 추론을 멈추지만, Pose의 손목·손가락·팔꿈치 좌표를 이용해 **계속 손바닥 중심을 추정합니다**. 따라서 둘 다 손바닥에 터치 원이 표시되는 것이 정상입니다.

실제 비교를 위해 각 손의 현재 입력 소스(HAND / POSE / 인식 없음)를 설정 패널에 표시합니다. **손의 터치 원이 청록색이면 HAND, 주황색이면 POSE 추정**입니다. 이는 모델이 로드됐는지 여부가 아니라 그 프레임의 실제 게임 앵커 선택을 기준으로 합니다. 스틱맨 선은 계속 Pose에서 가져오며, 토글을 꺼도 정밀 모델 객체는 현재 카메라 세션 동안 메모리에 있지만 추론은 중단됩니다.

평소 자세에서 두 모델의 위치가 비슷할 수 있으며, 추가 손 모델의 필요성은 다양한 각도/가림/반응속도/FPS를 실기기에서 비교해 판단합니다. `main` 병합은 별도 요청에 따른 fast-forward-only 규칙을 유지합니다.

## Vercel 자동 배포 정책 (2026-10-21)

저장소 루트 `vercel.json`에서 **`git.deploymentEnabled.dev = false`**, **`git.deploymentEnabled.main = true`**로 고정합니다. `dev` 푸시는 **Vercel에서 자동 Deployment/Build를 생성하지 않고**, `main` 푸시만 자동 프로덕션 배포합니다. 이는 단순 `ignoreCommand` (빌드 요청 후 skip)보다 낭비가 적습니다.

- 기능 개발: `dev`에서 작업하고 **GitHub Actions 테스트·TypeScript 검사·빌드는 계속 실행**합니다(이 CI는 Vercel 빌드 쿼터와 별개).
- 실기기 개발 테스트: localhost / GitHub Codespaces HTTPS / 사용자에게 승인된 임시 HTTPS 터널. `dev` 자동 Vercel Preview 링크는 만들어지지 않습니다.
- 릴리스: 검증된 `dev` SHA를 사용자가 승인하면 `main`으로 **fast-forward-only** 반영하고 Vercel 자동 배포합니다.
- 보충: 해당 규칙은 이 프로젝트의 Git 연동 자동 배포 정책입니다. **명시적 수동 배포, Deployment Hook, 다른 프로젝트의 자동 빌드**까지 차단하는 것은 아닙니다.

근거: [Vercel Git configuration](https://vercel.com/docs/project-configuration/git-configuration).

| `/play/balloon-pop` | 풍선 게임 카메라 시작·인식·일시정지·재개·종료·결과·전체 화면 |
| `/settings` | 화면 표시, 터치 크기, 카메라 방향, 정밀 손 추적, 입력 진단 |

- **카메라 권한은 게임 플레이 페이지에서 사용자가 명시적으로 시작할 때만 요청합니다.** 홈/탐색/설정 진입에서 카메라를 자동 실행하지 않습니다. 플레이 페이지에서 벗어나면 스트림·MediaPipe 인스턴스·AnimationFrame을 정리합니다.
- **표시 모드 빠른 전환**은 플레이 아래쪽에 남기고, 자세한 설정 UI는 `/settings`로 이전했습니다. 기존 손바닥 정밀 ON/OFF, 원 표시, 실제 판정 크기 옵션을 유지합니다.
- 공통 설정은 **현재 브라우저의 `localStorage`** 에 자동 저장됩니다(`sticktouch:settings:v1`). 영상·관절 데이터·게임 녹화는 저장하지 않습니다.
- `src/games/registry.ts`에 게임 카탈로그를 등록합니다. 현재 실행 가능한 게임은 **풍선 터뜨리기** 한 개이며, 과일 바구니/포즈 챌린지는 개발 예정으로 노출합니다. 그 외 게임을 플레이할 수 있는 것처럼 표현하지 않습니다.
- `src/app/App.tsx`와 `src/app/navigation.tsx`가 SPA 화면 전환을 담당합니다. `src/components/GameStage.tsx`가 카메라·추론 수명주기, `src/engine/renderer.ts`가 화면 그리기, `src/games/balloon-pop/game.ts`가 풍선 게임 규칙을 맡습니다. `src/settings/*`가 공통 설정을 관리합니다.
- Vercel의 `vercel.json`에 SPA deep-link fallback을 추가했습니다. 기존 **`git.deploymentEnabled.dev = false`** 자동 Preview 빌드 비활성화는 그대로 유지합니다. `main` 병합은 별도 승인 전까지 수행하지 않습니다.
- 게임별 난이도/시간, 사운드, 리더보드는 향후 기능입니다. 별도의 게임 설정 컴포넌트를 추가하기 쉬운 구조만 준비한 상태입니다.


## Game Feel Engine (2026-10-21)

공통 점수·콤보, Web Audio 기반 배경음악과 효과음, 파티클·점수 팝업, 강화된 HUD/결과 화면, 로컬 최고 기록을 dev 브랜치의 풍선 게임에 통합했습니다. 설정 → 게임 기본값에서 음악/효과음의 켜기·끄기와 볼륨, 시각 효과 품질을 선택할 수 있습니다. 소리는 사용자 게임 시작 클릭 시 활성화됩니다. 실제 모바일 실기기 성능과 오디오 재생은 아직 확인해야 합니다. 자세한 이벤트 계약과 개발 가이드는 [Game Feel Engine](docs/GAME_FEEL_ENGINE.md) 참고.
